# Pin 📌 — спецификация

Таск-трекер с markdown для Android. Работает полностью офлайн, синхронизируется с Google Диском папкой обычных
.md-файлов (совместимой с Obsidian) и отдаёт Крепости цифры о выполненных задачах.

## Записи

| Тип (`EntryType`) | Что это | Дата |
|---|---|---|
| `ONE_TIME` | Одноразовая задача: дата, необязательное время, приоритет, теги, описание в markdown с подпунктами `- [ ]` | день |
| `RECURRING` | Периодическая: каждый день, каждые N дней, по дням недели, ежемесячно (число или «последний день»), ежегодно | правило |
| `BIRTHDAY` | День рождения человека; год рождения по желанию (тогда показывается возраст). Напоминания за N дней (по умолчанию 7 и 1) и задача «Поздравить» в сам день | ежегодно |
| `HOLIDAY` | Праздник. Встроенный список: 1 и 7 января, 23 февраля, 8 марта, 1 и 9 мая, 12 июня, 4 ноября, 31 декабря; можно выключать и добавлять свои | ежегодно |
| `PLAN` | План на будущее: «когда-нибудь», месяц или год; превращается в задачу с датой | без точной даты |
| `GIFT` | Идея подарка для человека, привязка к поводу, цена, ссылка, статус «идея → куплен → подарен». За неделю до повода — «купить подарок», если ничего не куплено | по поводу |

Дни рождения и праздники — записи с ежегодным правилом, но без переноса: не выполненное в свой день «Поздравить»
закрывается как пропущенное, и запись встаёт на следующий год. Праздник — событие дня, не задача: в журнал не пишется.
Встроенные праздники имеют стабильные id `holiday-<ключ>` и только выключаются. Подарок — запись `GIFT` с человеком,
поводом (id дня рождения или праздника), ценой, ссылкой и статусом. План — запись `PLAN` с горизонтом `someday`,
`2026-12` или `2027`; превращение в задачу меняет тип той же записи.

Люди — отдельный справочник (имя, кто это: жена, друг, родственник); к ним привязаны дни рождения и подарки.

Приоритет — три уровня: низкий (0), обычный (1), важный (2). Выполнение важных задач Крепость видит отдельно.

## Логический день и перенос

- Сутки начинаются в границу дня (настройка, по умолчанию 04:00, как в Крепости). Отмеченное в 01:30 засчитывается вчера.
- Невыполненная в свой день задача переезжает на следующий день; счётчик «перенесено N раз» растёт, исходный день
  (`originalDay`) сохраняется. Выполнение вовремя — не позже исходного дня.
- Перенос детерминирован: зависит только от данных и сегодняшнего дня. Если приложение не открывали несколько дней,
  он досчитывается по одной ночи (каждая ночь — событие `ROLLED` в журнале). Повторный запуск ничего не меняет.
- Ручная смена даты — новый план: исходный день становится новой датой, счётчик переносов обнуляется.
- Периодическая задача (0.2): переносится невыполненный повтор, но когда наступает следующий повтор той же задачи,
  старый закрывается как пропущенный (`MISSED`) — без накопления дублей.
- Периодическая задача хранится одной записью: `originalDay` — день текущего повтора, `repeatAnchor` — от какого дня
  считаются повторы, `repeatRule` — правило (`daily`, `every 3 days`, `weekly mon,fri`, `monthly 15|last`, `yearly 03-08`).
  Выполнение пишет `DONE` с днём повтора и ставит следующий повтор (первый после дня повтора и дня выполнения);
  отмена возвращает повтор из журнала.
- Перенос выполняется при каждом открытии, на границе дня, пока приложение открыто, и в фоне (WorkManager).

## Журнал

Таблица `journal`: события `DONE`, `ROLLED`, `MISSED` с логическим днём, моментом, типом записи, приоритетом,
числом переносов и признаком «вовремя». Из него считается статистика и данные для Крепости; в файлы он выгружается
помесячно (`journal/2026-11.md`), чтобы статистика восстанавливалась из файлов. Отмена выполнения удаляет событие `DONE`.

## Экраны

- **Сегодня** — перенесённые сверху (самые «зависшие» первыми), задачи дня (важные, затем по времени), события дня,
  выполненные, ближайшие 7 дней.
- **Календарь** — месяц с точками событий.
- **Все записи** — фильтры по типу и тегам.
- **Люди и подарки**, **Планы**, **Статистика**, **Настройки**.
- **Редактор** — markdown с предпросмотром (заголовки, списки, чекбоксы, жирный/курсив, ссылки); чекбоксы отмечаются
  прямо в предпросмотре.
- **Быстрое добавление** одной строкой: «завтра купить хлеб», «в пятницу…», «12 ноября…».
- Уведомления: утренняя сводка дня и напоминания по времени. Виджет «Сегодня».

## Уведомления

Один будильник AlarmManager на ближайшее событие: напоминание по времени задачи, утренняя сводка (по умолчанию 08:00)
или граница дня. При срабатывании показывается всё наступившее (каждое напоминание — один раз, пропущенные больше чем
на 6 часов не догоняются) и ставится следующий. Расписание — чистые функции `engine/Reminders.kt`. После перезагрузки,
обновления и смены времени будильник ставится заново.

## Статистика

Выполнено/запланировано по дням, неделям, месяцам; доля выполненных вовремя; переносы и пропуски; серии дней без долгов;
разбивка по типам и тегам; самые «зависшие» задачи. Графики — на Compose Canvas.

## Хранение и синхронизация

- Источник истины на телефоне — Room. Удаление — пометкой.
- Формат обмена — папка .md-файлов: одна запись = один файл с YAML-шапкой, журнал по месяцам. См. `docs/FORMAT.md`.
- Google Диск через Drive REST API, вход через Credential Manager + Authorization API, область `drive.file`, папка «Pin».
  Фон — WorkManager, плюс кнопка. Конфликты — по `updated`, проигравшая версия сохраняется копией.
- Резерв — экспорт/импорт всей папки в zip через системный выбор файла.

## Крепость

Провайдер `com.sonnik.pin.ecosystem` (разрешение экосистемы): `info`, `day_stats`, `completions` — только цифры,
без названий задач и имён. Подробно — `docs/CONTRACT.md` (этап 0.7).
