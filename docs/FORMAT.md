# Формат файлов Pin

Папка «Pin» — обычные .md-файлы, которые открываются в Obsidian и правятся руками. Её создаёт экспорт в zip
(«Настройки → Данные») и синхронизация с Google Диском. Код: `engine/MdDoc.kt` (шапка, журнал), `data/MdFiles.kt`
(поля записей и людей).

```
Pin/
  tasks/2026-11-05 Купить хлеб.md   одноразовые (с датой в имени) и периодические задачи
  birthdays/Поздравить Аня.md       дни рождения
  holidays/День России.md           праздники, встроенные и свои
  gifts/Наушники.md                 подарки
  plans/Съездить в Казань.md        планы без даты
  habits/Зарядка.md                 привычки (repeat — дни недели, repeat_from — с какого дня; отметки — в журнале)
  people/Аня.md                     люди
  lists/Дом.md                      списки (проекты)
  journal/2026-11.md                журнал событий за месяц
```

Запись опознаётся по `id` в шапке, а не по имени файла: файл можно переименовать или перенести в другую папку.
Одинаковые имена различаются хвостом ` (первые 8 знаков id)`.

## Запись

```markdown
---
id: 6f1c2a9e-3b7d-4c55-9f0e-2d8a1b7c4e10
type: one_time
title: Купить хлеб
due: 2026-11-05
original: 2026-11-03
time: "18:30"
priority: normal
tags: [дом, магазин]
rollovers: 2
status: open
created: 2026-11-01T21:05:00+03:00
updated: 2026-11-05T08:12:44+03:00
---
Бородинский, если будет.

- [ ] хлеб
- [x] молоко
```

| Поле | Значение |
|---|---|
| `id` | UUID записи; файл без `id` при импорте получает новый |
| `type` | `one_time`, `recurring`, `birthday`, `holiday`, `plan`, `gift`, `habit` |
| `title` | заголовок; если нет — берётся первая строка `# …` тела |
| `due` | текущий день записи, `YYYY-MM-DD` (для периодических — день, куда перенесён текущий повтор) |
| `original` | исходный день (день повтора); пишется, только если отличается от `due` |
| `time` | `HH:MM` |
| `remind_before` | напомнить заранее, минут (5, 15, 30, 60) |
| `priority` | `low` / `normal` / `high` (или `0`/`1`/`2`) |
| `tags` | список `[a, b]`, строки `- a` под ключом или строка через запятую |
| `list`, `list_id` | список (проект): имя и его id (при импорте важнее `list_id`; по одному имени ищется существующий список) |
| `rollovers` | счётчик переносов |
| `status` | `open` / `done` / `missed` |
| `completed`, `completed_day` | момент и логический день последнего выполнения |
| `repeat` | правило: `daily`, `every 3 days`, `weekly mon,wed,fri`, `monthly 15`, `monthly last`, `yearly 03-08` |
| `repeat_from` | день, от которого отсчитываются повторы |
| `person`, `person_id` | человек: ссылка Obsidian `[[Имя]]` и его id (при импорте важнее `person_id`) |
| `birth_year` | год рождения (дни рождения) |
| `remind` | за сколько дней напоминать: `[7, 1]` |
| `gift_status`, `price`, `link`, `occasion` | подарок: `idea`/`bought`/`given`, цена, ссылка, id повода |
| `plan` | горизонт плана: `someday`, `2026-12`, `2027` |
| `disabled` | `true` — праздник выключен |
| `deleted` | `true` — запись удалена (передаётся при синхронизации) |
| `created`, `updated` | ISO-8601 со смещением; `updated` решает конфликты |

Тело после шапки — описание в markdown как есть.

## Человек

```markdown
---
id: 0b6d…
type: person
name: Аня
relation: wife
created: …
updated: …
---
Заметка о человеке.
```

`relation`: `wife`, `husband`, `family`, `friend`, `colleague`, `other` или своя категория текстом (`крёстный`).

## Список

```markdown
---
id: 5a1e…
type: list
name: Дом
color: green
order: 0
created: …
updated: …
---
```

`color`: `red`, `orange`, `amber`, `green`, `teal`, `blue`, `violet`, `gray`. Удалённый список — `deleted: true`;
его задачи остаются без списка.

## Журнал

```markdown
---
type: journal
month: 2026-11
---
| day | event | id | at | kind | priority | rollovers | on_time | occurrence |
|---|---|---|---|---|---|---|---|---|
| 2026-11-03 | ROLLED | 6f1c2a9e-… | 2026-11-04T04:00:00+03:00 | one_time | 1 | 1 |  | 2026-11-03 |
| 2026-11-05 | DONE | 6f1c2a9e-… | 2026-11-05T18:40:00+03:00 | one_time | 1 | 2 | false | 2026-11-03 |
```

События: `DONE` (выполнено), `ROLLED` (ночь переноса, `day` — невыполненный день), `MISSED` (пропущенный повтор,
`day` — день повтора), `FOCUS` (отрезок фокус-таймера: `id` — задача или `focus`, `rollovers` — минуты фокуса). Столбцы ищутся по заголовку — порядок не важен. При импорте события добавляются без дублей
(ключ — id, событие, день, момент).

## Правила чтения

- YAML — упрощённый: `ключ: значение`, строки в двойных или одинарных кавычках, списки `[a, b]` или `- a`,
  комментарии ` # …`. Переводы строк Windows не мешают.
- Неизвестные поля сохраняются и записываются обратно при экспорте.
- Поля, которых в файле нет, не сбрасывают данные уже существующей записи.
- Файл без шапки читается: заголовок — первая строка `# …`, без даты он становится планом «когда-нибудь».
- Файл без заголовка пропускается и упоминается в итоге импорта.
- Слияние: запись из файла применяется, если её `updated` новее, чем в приложении.
